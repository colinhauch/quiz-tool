# Distractors

Wrong answers are where multiple-choice questions are actually made or ruined, and they get their own file because the reasoning is not obvious from the code.

## Distractors come from the graph

Never invented, never random. A wrong answer is a real entity or a plausible real value, pulled from the same graph as the right one.

This is not aesthetic. **The graph is what makes a distractor's wrongness checkable.** A generated wrong answer might accidentally be right — offer "Peru" as a wrong answer to "which country borders Brazil" and the question is broken. Drawing from the graph means we can query for entities that satisfy the type constraint and *do not* satisfy the relation, and be certain.

## The invariant: type-valid, always

**A distractor must satisfy the relation's range types, or the answer is guessable without knowing anything.** Offer a river among three countries and the question tests reading comprehension, not geography.

This is the one rule here that is not negotiable, and it is why relation types declare domain and range at all. Type constraints exist for import validation, but this is the other half of their job — see [../knowledge-graph/](../knowledge-graph/).

## Difficulty lives in the distance

Given type validity, the remaining dial is **graph distance**: how close the wrong answers are to the right one.

Other South American countries that don't border Brazil are hard — the learner must know the actual border, not just the continent. Mongolia is easy — anyone who knows Brazil is in South America eliminates it without knowing a single border. Same fact, same template, wildly different difficulty, and the difference is entirely in the distractor pool.

That is the insight worth carrying: **distractor selection is where a question's difficulty mostly comes from**, more than option count or input mode. A question with lazy distractors tests continent knowledge while claiming to test border knowledge, and the answer log will record a skill the learner doesn't have.

## Numeric distractors are a different problem

For quantities there is no "sibling entity" to draw from, so wrong values are generated by scaling the true one. The scaling factors are what make an order-of-magnitude question test order of magnitude — offer values within 10% of truth and it becomes exact recall through the back door, which is the thing numeric questions exist to avoid. See [README.md](README.md).

## Current strategies

*Snapshot for orientation — the code owns the registry. If these disagree, the code is right.*

As of this writing: `siblings` (same type, near in graph — hard), `same_type_far` (same type, distant — easy), `same_range` (anything type-valid — the baseline that only guarantees the invariant), and `literal_spread` (scaled numeric values).

If you are adding a strategy, the question to answer is what *kind of knowledge* it isolates — every strategy above exists because it makes a question test something specific.
